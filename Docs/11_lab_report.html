Lab Report · Live-Test Findings

Improving the Live NILM System: what we would build next

CourseModeling, Simulation and Automation of Electrical Energy Systems, TH Koeln
SystemLive NILM monitor — live.py
TeamSoheil Ayati (11153003), Marc Steffgen (11149043)
Date2026-07-22

Our system disaggregates per-appliance power from a single PAC4200 measurement, logs every switch event with exact timestamps, and learns unknown devices on the go. It performed well in the live evaluation. This report collects the concrete weaknesses we observed during those tests and the improvements we would prioritise next. Each point states what the software does today, why it is a limitation, and the proposed change.

Improvement points

01

A graphical event timeline

Now
Switch events are written to events.csv and shown on the dashboard as a scrolling text log. Measured power is charted, but the ON/OFF history of individual devices is not.
Gap
Reading a text log line by line does not reveal overlap between devices, missed edges, or a claim that flickered — all of which are obvious at a glance on a timeline.
Fix
Render a per-device Gantt-style timeline (one lane per device, coloured ON intervals on a shared time axis) beside the power chart. The event log already carries exact edge timestamps and the matched device, so no new data is needed, only the view. It doubles as a post-test artifact for reporting and debugging.
02

Faster, more precise corrections

Now
When a device's steady state changes shape, the engine can briefly misread it before a second evidence source corrects it. In the live test at ~16:01 the PV export was released as OFF for about ten seconds, then the residual monitor re-matched its signature and restored it to ON.
Gap
A PV generation ramp is a step of (dP, dQ ≈ 0), indistinguishable in the (P, Q) plane from a small switching supply turning off, so the off-edge wrongly released the PV claim. The correction is real but slow: it waits for the residual monitor's multi-second window to accumulate.
Fix
Move the discriminating evidence to the moment of the edge. A true switch carries the device's harmonic current with it; a generation ramp carries none. Applying that harmonic-and-sign test at edge time, plus a short hold before a generator claim is released, would shorten the ten-second correction to a fraction of a second instead of detecting and undoing the mistake after the fact.
03

Generic load-class labels for unknown devices

Now
Teaching an unknown load requires the user to type a specific name (standing_fan_high, coffee_machine_standby). The signature table and identify model are keyed to that exact family.
Gap
In a real installation the operator often knows only that something new is drawing power, not its family. Requiring a specific name makes the system brittle and unhelpful for unfamiliar devices.
Fix
Offer an automatic electrical-class label from features we already measure — resistive, inductive, capacitive, non-linear (switch-mode). The sign of Q separates inductive from capacitive; power factor and THD_I separate a clean heater from a distorted supply. Our own fingerprint table shows these classes are cleanly separable here (THD_I ~2 % for the boiler vs ~170 % for the laptop). The user can still refine the label into a name later, but the system is useful immediately.
04

Fully asynchronous, hands-off training

Now
The in-mix teach removed the need to empty the mains, but still asks for one manual action: switch the unknown device off and back on once so the settled step gives a model-free measurement of its draw.
Gap
Any required action interrupts an experiment and is impossible for loads that cannot be toggled (a running fridge, an inverter, a sealed installation). It also blocks unattended, continuous learning.
Fix
Learn passively from the residual history the engine already records. When unexplained power appears and persists, capture its settled level, Q, and harmonic signature over time and teach a provisional signature from that alone, cross-checked against any natural on/off transitions that occur. The manual toggle becomes an optional confidence boost, not a prerequisite — training a background process the user never has to trigger.
05

Recognition across a device's operating range

Now
A device is taught at whatever it drew during capture. A switching supply or PV inverter whose output varies can then fall outside the taught range and stop matching (the laptop taught at 66 W idles at 43 W; PV taught near −13 W was seen at −30 W).
Gap
Variable-output loads and generation are exactly the cases NILM finds hardest, and a single taught operating point does not cover them.
Fix
Teach a range rather than a point — record several operating levels, or let a distinctive harmonic fingerprint taper the match toward idle. For PV, the unique, load-independent discriminator is the sign of power, which no consumer produces, so generation should be recognised by sign across its whole range rather than by a taught wattage.

Summary

The system met the goals of the exercise. The improvements above target the gaps we felt during live operation: better visibility (timeline), faster self-correction (edge-time harmonic evidence), lower operator burden (generic labels and hands-off learning), and robustness to the hardest loads (variable-output devices and generation). None require new sensing hardware; all build on features the pipeline already records.
